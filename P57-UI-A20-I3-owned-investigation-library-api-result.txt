6. Investigation creation command

POST /api/v1/investigations requires a valid authenticated cookie session and the
A20-I1 double-submit/server-digest CSRF proof. The strict request fields are title
(1–200 characters), optional objective (up to 2,000 characters), and idempotencyKey
(1–200 characters). Unicode is NFKC-normalized, outer whitespace is removed, blank
values and control characters are rejected, and unknown fields are forbidden.

7. Server-generated identity

The service generates inv_<32 lowercase UUIDv4 hex characters> using Python UUIDv4,
which uses the platform cryptographic random source. Caller-selected IDs are rejected.
Generation does not derive from title, owner, email, time, canon, or browser state.
Unique-key collisions are retried up to eight times and then fail closed as repository
unavailability; deterministic collision verification proves no ownership transfer.

8. Parent ownership behavior

owner_principal_id is always principal.account_id from
require_csrf_protected_principal. No header, body, query, frontend identity, child row,
or WorkspaceRuntime value can select or alter ownership. Persisted parent lookup
remains the authority for reads and all committed child routes.

9. Empty aggregate behavior

Every created parent has exactly one investigation-aggregate/v1 row with state EMPTY
and revision 0. The parent lifecycle remains ACTIVE in the established parent schema;
here ACTIVE means library-visible/not archived, not activated in WorkspaceRuntime.
Parent version is 0 and created/modified timestamps are equal UTC instants. The
aggregate has no graph, node, edge, workspace, selection, layer, Inbox, experiment,
author, Candidate Evidence, Research Source, or STUDIO fields.

10. Idempotency behavior

The durable key scope is (owner_principal_id, CREATE, idempotency_key). Its command
hash covers normalized title and objective. Same-account/key/payload replay returns
the original parent and aggregate with replayed=true. Changed content returns
IDEMPOTENCY_KEY_REUSE. Different accounts may reuse the client key independently.
The receipt is written in the same transaction and failed commands leave no receipt,
so a safe retry is not poisoned.

11. Owned list projection

GET /api/v1/investigations returns only current-account parents with safe identity,
title, objective, lifecycle, timestamps, and version. It exposes no owner, account,
session, credential, or security data. Ordering remains modifiedAt descending and
investigationId ascending as a stable tie-breaker. Fresh accounts return successful
EMPTY semantics as an empty items array.

12. Owned detail projection

GET /api/v1/investigations/{id} first resolves the parent by exact authenticated
owner and then resolves its empty aggregate through an owner-joined query. The safe
versioned response contains parent version plus aggregate schema/state/revision.
Foreign and absent IDs both return the same INVESTIGATION_NOT_FOUND envelope and do
not reveal another account identity.

13. System-owned canonical separation

No system-owned Investigation policy or discriminator was invented. Canonical
frontend/repository inspection remains separate. Creation cannot accept lifecycle,
system status, canonical state, seeded events, nodes, or edges. No Nimitz, Tic Tac,
default, Guest, fixture, copied-system, or canonical content is inserted or returned.

14. Transaction and rollback behavior

SQLite BEGIN IMMEDIATE wraps parent, aggregate, and idempotency insertion. Any error
rolls back all three. Foreign keys are enabled per connection. An injected aggregate
failure test proves zero parent, aggregate, and idempotency rows remain, followed by
a successful retry. Migration 002 is applied atomically and backfills migration-001
metadata-only parents with the only truthful EMPTY aggregate; it neither guesses nor
changes ownership and creates no content. Newer schema versions remain rejected.
