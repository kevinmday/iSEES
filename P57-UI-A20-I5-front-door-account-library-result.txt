VERIFIED ROOT CAUSES

- AccountFrontDoor treated its useEffect cleanup as an ownership transition and
  called operatorIdentityRuntime.clearIdentity(). React StrictMode effect replay,
  hot replacement, component unmount, and reload teardown could therefore delete
  a valid session-scoped guest identity without an explicit termination command.
- Continue as guest used coordinator.beginNewPrincipalEpoch(). That account
  boundary operation is intentionally destructive: it deactivates Workspace and
  clears Research/Author state. A fresh guest command could therefore erase the
  runtime immediately before the real shell mounted, producing the blank shell.
- Account session restoration began before identity hydration was resolved. The
  Front Door now waits for READY identity state and gives an already-hydrated guest
  precedence, so it cannot decide anonymous state while guest hydration is pending.

LIFECYCLE, HYDRATION, AND EXPLICIT TEARDOWN OWNERSHIP

- AccountFrontDoor cleanup now only aborts its request generation and invokes the
  coordinator's cancellation-only path. It never clears identity or operational
  workspace state.
- AccountWorkspaceContinuityCoordinator.cancelPendingRequests() advances both
  stale-response guards and aborts its controller without deactivating Workspace,
  clearing Research/Author, or changing principal ownership.
- Continue as guest uses that cancellation-only path before the established
  operatorIdentityRuntime.continueAsGuest() authority. It no longer invokes an
  account boundary reset capable of blanking the guest workspace.
- The restoration effect is gated on identity status READY. A restored GUEST goes
  directly to ready real-shell projection; anonymous/account restoration runs only
  after identity hydration resolves.
- Explicit Sign in/Create account from Guest still stops guest capture, clears the
  guest workspace snapshot and guest identity, performs the account boundary reset,

OWNERSHIP ROOT CAUSE AND ATOMIC POLICY

Identity and workspace persistence were individually validated but not jointly
resolved before hydration. When the earlier lifecycle defect removed the same-tab
Guest identity, Continue as guest minted and persisted a new identity while the old
valid workspace snapshot remained. Lifecycle start then passed both owners to the
restorer, whose correct mismatch assertion threw from a React effect.

Restoration now makes one production policy decision before calling any runtime
hydrator. A valid snapshot and matching READY/GUEST/SESSION identity restore normally.
If identity is missing, Continue as guest reestablishes the exact identity from the
fully structurally validated same-tab ownership envelope, persists it first, and only
then allows lifecycle hydration. An already-valid but different current Guest wins:
the stale snapshot is rejected and cleared; it is never exposed to hydration.

STALE, MALFORMED, AND UNSUPPORTED RECOVERY

Mismatch, invalid JSON, malformed structure, and unsupported schema all converge on
a clean usable Guest workspace. Workspace is deactivated into OVERVIEW, computational
and focused state are cleared, and Research/Author state is cleared while lifecycle
capture is suppressed. A new coherent empty snapshot is then captured under the
current valid Guest, allowing the recovered session to persist and reload normally.
The Guest warning remains visible and adds: “Your prior temporary guest work could
not be restored. A clean guest workspace is ready.” Diagnostics are fixed non-secret
codes (OWNERSHIP_MISMATCH, INVALID_SNAPSHOT, RESTORE_FAILURE); no Guest IDs are logged
by the recovery path.

ERROR CONTAINMENT

GuestWorkspaceRestorationBoundary now surrounds OperatorUI inside the existing
identity gate. It is defense in depth after deterministic lifecycle handling. An
unexpected restoration/composition exception projects an iSEES-branded explanation
and a Return to Front Door action; it contains no stack or internal identifier. That
action explicitly clears temporary Guest restoration state and returns to the normal
Front Door, where Continue as guest and account access remain available.
