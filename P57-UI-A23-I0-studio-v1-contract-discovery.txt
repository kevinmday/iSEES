PURPOSE AND METHOD

This report records facts observed in the existing tracked and untracked tree. No
production file was changed. Status terms are:

  IMPLEMENTED AND TRACKED  present in Git at the inspected HEAD/worktree.
  IMPLEMENTED BUT UNTRACKED present only in the pre-existing untracked worktree.
  PARTIAL OR PLACEHOLDER    a seam/UI/type exists but does not satisfy the canon.
  ABSENT                    no implementation was found in the inspected paths.
  CONTRADICTS CANON         existing behavior or vocabulary conflicts with A23 canon.
  UNKNOWN / REQUIRES DECISION evidence is insufficient or product/operations policy is needed.

EXECUTIVE FINDING

The repository has a substantial, coherent A16/A17 STUDIO spine: investigation-
qualified routing, a three-column shell, Research Inbox insertion, a structured
ComputationalAuthorDocument runtime, strict drafting request/proposal contracts,
SQLite artifact/version/snapshot persistence, optimistic revision and idempotency,
lifecycle records, deterministic hashing, a real deterministic PDF materializer,
and backend tests. It is not the A23 V1 product. The current profiles, source
classifications, projection lifecycle, AI audit/apply model, scientific semantics,
sensitivity rules, Inference Box, publication semantics, and authentication/browser
contract do not yet meet the final canon.

The safest path is extension and convergence, not wholesale replacement. Preserve
the active untracked save orchestration work, freeze the A23 domain/wire contract,
then adapt existing owners behind it in small verified increments.

2. .AUTHOR IDENTITY, CONTENT, REVISIONS, AND PERSISTENCE (ANSWERS 1–2)

IMPLEMENTED AND TRACKED

- In-memory identity/content: ComputationalAuthorDocument in
  author/model/AuthorDocument.ts extends AuthorDocument from AuthorDocumentTypes.ts.
  It has identity {id, createdAt}, semantic metadata, type/status, and an ordered
  union of typed nodes from AuthorNodeTypes.ts.
- Structured semantics exist for PARAGRAPH, HEADING, QUOTE, LIST, CODE, TABLE,
  IMAGE, CITATION, REFERENCE, OBSERVATION, DIVIDER, and CUSTOM. ReferenceNode embeds
  exact ResearchAnchor provenance. This is structured semantic content, not plain
  text, although several node semantics are too shallow for A23.
- Local .author transport: AuthorArtifactSerializer.ts emits versioned JSON;
  AuthorArtifactTypes.ts and AuthorArtifactParser.ts validate/restore it;
  AuthorKnowledgeCompiler.ts provides a separate explicit knowledge-ingestion path.
- Durable identity/revisions: StudioArtifact and StudioArtifactVersion in
  isees_uap/studio/models.py; create_draft/save_version in StudioService; tables
  studio_artifact and studio_artifact_version in migrations/001_studio.sql.
  StudioArtifact has stable artifact_id and current_version_id/number. Frozen
  StudioArtifactVersion has parent_version_id, document, content_hash, creator, and
  time. SQLiteRepository transactionally advances the head with expected revision.
- StudioAuthorDocumentAdapter.composeStudioVersionCommand maps the active structured
  document, eligible source-backed references, and OBSERVATION claims into backend
  commands. StudioDocumentRestoration revives required Date fields after retrieval.

PARTIAL OR PLACEHOLDER

- There are two save concepts: StudioToolbar local .author download and Artifact
  Inspector durable Save Draft. A23 requires distinct names/contracts, but the
  current toolbar button is simply “Save” and marks local runtime clean after file
  emission in the modified worktree. Local download is not backend authority.
- document.metadata.version and document.status are browser fields; the backend
  artifact revision/version is durable authority. They are not one reconciled
  revision contract.
- The backend stores document as unconstrained Any/JSON under a caller-supplied
  authorSchemaVersion. It does not validate the full semantic .author schema.

CONTRADICTS CANON

- Current local .author files and durable backend versions are parallel persistence
  representations without a single declared authority boundary. A23 requires one
  authoritative structured .author lineage.
- Saved-version creation does not automatically queue all enabled children.

Answer: AuthorDocumentRuntime owns unsaved identity/content; serializer/parser own
local .author transport; StudioService/SQLiteStudioRepository own durable artifact
identity and immutable versions. The document is structured, but the complete A23
semantic schema and unified authority contract are absent.

8. HISTORICAL 404/422 AND CURRENT SCHEMA MISMATCH (ANSWERS 7–8)

FACTUAL CAUSES

- Before commit 3e62270 (A16-I1C), Studio persistence routes were not mounted; calls
  to guessed Studio artifact URLs therefore returned 404.
- Routes intentionally return non-disclosing 404 for absent artifacts, wrong owner,
  wrong Investigation, path/body artifact mismatch, missing output, and unauthorized
  access. A 404 is not proof that the route is absent.
- Pydantic schemas use extra="forbid" and require command-specific fields. Mutation
  calls missing schemaVersion, investigationId, principalId, idempotencyKey, and for
  existing artifacts artifactId/expectedRevision return FastAPI 422. Invalid source
  kinds/classifications, malformed timestamps/hashes, or an older payload shape also
  return 422.
- First-save logic must POST the collection route with CreateStudioDraft; sending a
  SaveStudioArtifactVersion to an artifact URL before an artifact exists yields the
  wrong route/lifecycle behavior. A17 commits c4e6318 and 32fd303 addressed first-save
  and empty-state semantics.

CURRENT MISMATCHES

- composeStudioVersionCommand intentionally returns the document payload but not
  idempotencyKey/artifactId/expectedRevision; Inspector/orchestrator must add them.
  Calling the adapter result directly produces 422.
- Frontend StudioArtifactProjection omits backend versionHistory and audit arrays and
  models only a subset of snapshot fields. The backend response is wider; this is
  tolerated structurally but is not one generated wire contract.
- Local serialized .author uses its own artifact/schema envelope, while the backend
  expects authorSchemaVersion plus document Any. Upload bytes are not the same as a
  CreateStudioDraft command.
- The frontend sends X-ISEES-Principal-Id, but current server authority comes from an
  authenticated session cookie; mutations also require X-ISEES-CSRF. StudioApi.ts
  does not send the CSRF header. _ownership requires command.principalId equal the
  authenticated account_id, while the frontend uses operator.identity.operatorId.
  These identities require an explicit convergence contract.
- api/__init__.py CORS allow_headers includes Content-Type, X-ISEES-CSRF, and
  X-Request-Id, but not X-ISEES-Principal-Id. Cross-origin browser preflight can fail
  even though the header is ignored for authentication.

12. AUTHENTICATION, PRINCIPAL HEADERS, CORS, SECURITY, AND PRIVACY (ANSWER 19)

IMPLEMENTED AND TRACKED

CONTRADICTS CANON / BLOCKER

human granular acceptance; and egress tests proving excluded sources never appear in
prompts, logs, telemetry, exports, or errors.

15. EXISTING CONTRACTS TO EXTEND AND ELEMENTS TO REPLACE (ANSWERS 11–12)
