\# RESOLVE–DISSOLVE COMPUTATION (RDC)

\# ============================================================



\## Abstract



Resolve–Dissolve Computation (RDC) is the foundational computational

engine of iSEES.



RDC defines the computational universe in which an investigation is

performed. Rather than filtering existing information, RDC repeatedly

recomputes the entire Investigation Manifold using different sets of

active computational layers.



Every change to computational context produces a new deterministic

topology.



The resulting manifold is therefore not a visualization of existing

knowledge.



It is the computational product of the currently selected

investigative assumptions.



\---



\# 1. Motivation



Traditional analytical systems employ static layers.



Layers are typically used only for visualization.



Turning a layer on or off merely changes what the operator sees.



The underlying data relationships remain unchanged.



RDC rejects this model entirely.



Instead,



every computational layer contributes directly to the mathematical

construction of the Investigation Manifold.



Removing a layer changes the mathematics.



Changing the mathematics changes the topology.



Changing the topology changes the conclusions.



\---



\# 2. Core Principle



Resolve–Dissolve Computation is founded upon one central principle:



> Every change to the computational universe requires a complete

> deterministic recomputation of the Investigation Manifold.



Nothing is merely hidden.



Nothing is merely shown.



The manifold itself changes.



\---



\# 3. Resolve



Resolve represents the introduction of computational information.



Examples include:



• enabling additional computational layers



• importing investigations



• importing artifacts



• enabling research profiles



• expanding temporal scope



• increasing investigative scale



Resolve increases available computational context.



\---



\# 4. Dissolve



Dissolve represents the removal of computational information.



Examples include:



• disabling computational layers



• reducing temporal scope



• removing investigations



• excluding evidence



• restricting investigative scale



Dissolve intentionally removes assumptions from the computation.



\---

\# 7. Emergent Topology



The resulting topology is an emergent mathematical structure.



During recomputation



nodes may



• appear



• disappear



• merge



• split



Likewise,



edges may



• strengthen



• weaken



• disappear



• emerge



Entirely new investigative structures may appear that were absent

under previous computational assumptions.



This behavior is intentional.

\---



\# 10. Design Philosophy



Resolve–Dissolve Computation is not a visualization system.



It is not a graph engine.



It is not artificial intelligence.



It is a deterministic computational framework whose purpose is to

construct investigative topology from explicitly defined assumptions.



Every result must be reproducible.



Every result must be inspectable.



Every result must be mathematically explainable.



No hidden reasoning exists.



\---



\# 11. System Canon



The following statements constitute system canon.



• RDC defines the computational universe of an investigation.



• Computational layers influence mathematics rather than visualization.



• Every computational change requires complete manifold

&#x20; recomputation.



• The Investigation Manifold is an emergent deterministic topology.



• New investigative structures may legitimately emerge following

&#x20; recomputation.



• RDC is the only subsystem responsible for computational layers.



• All downstream reasoning engines consume RDC output.



\---



\# Conclusion



Resolve–Dissolve Computation is the computational heart of iSEES.



Rather than filtering information, RDC continuously reconstructs the

investigative topology from first principles using deterministic,

inspectable mathematics.



This architectural decision allows previously unseen relationships,

clusters, contradictions, and ultimately candidate intentions to emerge

as natural consequences of changing the computational universe rather

than changing the visualization of existing data.



SC-001 therefore establishes the foundational computational philosophy

upon which every subsequent component of iSEES is built.
