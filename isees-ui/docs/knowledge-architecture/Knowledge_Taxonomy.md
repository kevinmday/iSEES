\# Knowledge Taxonomy



\## Purpose



This document establishes the official taxonomy governing the classification

of knowledge within iSEES.



Every architectural document shall declare exactly one primary Knowledge Type.



Knowledge Types classify the nature of the knowledge represented.



They do not indicate document quality, maturity, or repository location.



\---



\# Knowledge Types



\## Computational Foundation



Defines objective computational principles governing iSEES.



Examples



\* Resolve–Dissolve Computation

\* Computational Layers

\* Investigation Manifold

\* Deterministic Discovery

\* Intention Engine



\---



\## Cognitive Architecture



Defines models of investigator cognition and human interaction with iSEES.



Examples



\* Investigation Workbench

\* Cognitive Workspace

\* Attention Management

\* Knowledge Navigation



\---



\## Engineering Architecture



Defines how computational principles are realized through software

architecture.



Examples



\* Workspace Architecture

\* Runtime Boundaries

\* Subsystem Architecture

\* Component Responsibilities



\---



\## Runtime Architecture



Defines the behavior of executing software.



Examples



\* Runtime State

\* Session Lifecycle

\* State Synchronization

\* Projection Runtime



\---



\## Research Methodology



Defines how investigations are conducted using iSEES.



Examples



\* Research Authoring

\* Evidence Organization

\* Corpus Federation

\* Narrative Construction



\---



\## Domain Knowledge



Defines knowledge specific to a research domain.



Examples



\* UAP

\* Aviation

\* Intelligence

\* Historical Investigations



\---



\## Historical Doctrine



Defines historical architectural documents retained for provenance.



These documents explain architectural evolution but no longer govern

implementation.



Examples



\* Early architectural direction

\* Superseded design documents

\* Historical doctrine



\---



\# Classification Rules



Every document shall declare exactly one primary Knowledge Type.



Documents may reference multiple knowledge domains, but ownership remains

singular.



Knowledge Type shall remain stable unless the purpose of the document changes.



\---



\# Architectural Invariants



Knowledge Type defines what a document fundamentally represents.



Knowledge Type is independent of



\* repository location

\* implementation status

\* document age

\* engineering session

\* canonical identifier



Knowledge Types classify knowledge.



They do not classify files.
