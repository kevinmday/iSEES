6. Backend activation projection

The distinct activation subresource reuses the A20-I3 service and exact persisted
parent ownership query; it does not introduce competing authorization. It was kept
distinct because ordinary detail is a library metadata contract while activation
must explicitly expose runtime semantics. The projection contains activation and
aggregate schema versions, parent and aggregate revisions, lifecycle, safe display
identity, RESEARCHER_OWNED access kind (without owner data), deterministic freshness
token, explicit empty graph collections, null focus, and stable workspace identity.
The GET performs no mutation and requires no CSRF.

7. Frontend validation boundary

The strict parser requires exact keys, supported schemas, requested identity,
ACTIVE lifecycle, timezone timestamps, non-negative safe versions/revisions,
owner-access kind, freshness-token consistency, and exact EMPTY semantics. Unknown,
missing, malformed, foreign-identity, focused, or non-empty data fails before any
runtime mutation. Transport, authentication, not-found, invalid, stale, and network
failures remain distinct.

8. Atomic WorkspaceRuntime activation

activateEmptyOwnedInvestigation publishes status, Workspace, Investigation, cleared
selection, empty computational layers, null focused Event, and one revision/notify
transition. The canonical operational-revision activation remains unchanged and
strict. The coordinator validates and materializes completely before entering its
non-throwing coordinated publication sequence. Failed fetch or validation preserves
the prior valid workspace unless authentication security requires teardown.

9. Empty Investigation behavior

The resulting workspace has no imported Event, focused Event, graph node, graph
edge, artifact, active layer, revision, comparison, selection, Inbox entry, Candidate
Evidence, Research Source, experiment, or author document. No default Investigation,
Nimitz/Tic Tac fixture, or canonical materialization is consulted or injected.

10. Last-active persistence and account scoping

Only the non-sensitive Investigation ID is stored under
isees.account.lastActiveInvestigation.v1:{encodedAccountId}. It is written only after
successful activation. The value is a request reference, never identity or access
authority. No session, CSRF, password, owner record, selection, or draft is stored.

11. Reload restoration sequence

restoreSession obtains the server cookie-session projection with credentials,
establishes a new principal epoch, reads only that account's reference, refetches the
activation projection, reauthorizes server-side, validates it, and activates. Missing
or foreign references leave WorkspaceRuntime inactive with no fallback.

12. Logout teardown inventory

The coordinator cancels/invalidate requests, deactivates WorkspaceRuntime (workspace,
Investigation, focused Event, artifacts, selection, layers, temporal and scale
configuration), and invokes registered account-sensitive teardown owners. Production
owners now expose clearing seams for ResearchBridge/Research Inbox, all cached and
active Author documents, and Investigation Library cache. The registry contract is
also the seam for React-owned comparison, OVERVIEW selection/modal, Resolve, LAYERS,
Candidate Evidence, Research Sources, STUDIO drafting, and other provider-local
owners when composed by the later application boundary. Coordinator identity,
revision cache, active reference, and in-memory principal are cleared.

13. Account-switch sequence

beginNewPrincipalEpoch or a changed restored researcher first increments the epoch,
aborts pending I/O, deactivates the prior workspace, clears registered subordinate
owners and revision memory, then publishes the new clean principal. Only the new
account's keyed reference may subsequently be restored.

14. Late-response and stale-response protection

Every activation captures principal, epoch, and monotonically increasing request
generation. Logout, account replacement, a newer activation, or new session restore
aborts and invalidates it. Responses must still match all three values. Per-
Investigation aggregate revision memory rejects a lower revision, and the freshness
token must equal parentVersion:aggregateRevision. Remembered-reference work uses the
same generation checks.

15. Session expiration behavior

A 401 during session restore publishes AUTHENTICATION_REQUIRED/SESSION_EXPIRED after
full boundary teardown. A 401 during an owned activation immediately performs the
same privileged-state teardown. There is no principal-header or Guest fallback.

16. API credential and CSRF behavior

The new API sends credentials: include for every request and sends no researcher or
principal authority header. Safe session/activation GETs omit CSRF. Logout POST sends
only X-ISEES-CSRF and cookie credentials. Raw sensitive values are not persisted.
