ROOT-CAUSE TRACE AGAINST HEAD

1. Guest-session restoration
   HEAD restores the persisted Author document directly into AuthorDocumentRuntime. JSON persistence converts Date fields to strings. ResearchBridgeRuntime.restoreDesk is already an authoritative hydration boundary and calls migrateResearchAnchor, which revives and validates Research Anchor collectedAt/createdAt. Author restoration has no equivalent call in HEAD.

2. Author document activation / Investigation switching
   StudioShell activates AuthorDocumentRuntime for the active Investigation. AuthorDocumentRuntime retains one document and dirty flag per Investigation and refuses stale canonical reconciliation by checking Investigation, document identity, and revision. The provider wrapper does not repair these behaviors and broadens their component lifetime unnecessarily.

3. Source insertion
   createAuthorReferenceFromResearchAnchor stores insertedAt and the frozen publication/provenance fields already required by StudioAuthorDocumentAdapter: anchor/source identities, source revision, classification, insertability, and capturedRepresentation. ResearchAnchor remains in the persisted Research Desk, whose restore boundary already revives its schema-defined Date fields. Copying the complete graph anchor and extra dates/display onto AuthorNodeTypes is not required by runtime publication.

4. Source-backed save / first creation / later version creation
   HEAD's Inspector owns Save Draft. It composes snapshots, publishes each available GRAPH Research Anchor first, then invokes mutate for the initial create or version route. The confirmed stop occurs synchronously inside composeStudioVersionCommand when node.insertedAt is a persisted string and `.getTime()` is called. Hydrating Author dates before runtime activation repairs this root cause. Save should remain Inspector-owned, but its operation should be awaited locally so stage-aware failures and canonical refresh are deterministic.

5. Toolbar Save
   HEAD deliberately downloads the native canonical `.author` JSON artifact. It is an established local export convenience and does not mark canonical Studio state clean. Replacing it with Inspector Save Draft changes behavior and availability and is not required by any confirmed defect.

6. Inspector Save Draft / error rendering
   HEAD routes all operation errors through the Inspector's global RequestState/message, which makes a failed save appear to be whole-artifact ERROR. A separate Inspector-local save-operation error is required. It must preserve the loaded canonical artifact, dirty runtime document, provenance, and historical projections; report source publication, version POST, canonical reconciliation, or local preparation accurately; and never claim v2 without an exact canonical refresh.

7. PDF validation / materialization / download
   HEAD gates validation on durable saved version and clean state, materialization on current validated PDF readiness plus ownership and synchronization, and download on a materialized PDF output identity. A dirty v2 draft does not erase a v1 projection. The only required UI addition is an explicit stale-output note; save failure must not replace artifact state or projections.

8. Projection consistency
   activeStudioContentHash plus AuthorDocumentRuntime.reconcileCanonicalState owns clean-state transition. It is revision-, document-, and Investigation-guarded. Save code must adopt only the exact refreshed canonical version and leave hash reconciliation as the clean transition.

9. Startup migration
   HEAD creates/reads studio_schema_migrations before BEGIN IMMEDIATE and starts a separate transaction per pending migration. Two cold starters can make the same stale decision. The fix belongs wholly in SQLiteStudioRepository._migrate: acquire BEGIN IMMEDIATE before creating/reading history and apply all pending migrations and history rows in one transaction, rolling back and surfacing unexpected failures.

10. API errors / request IDs
    Canonical StudioApi errors sanitize messages. requestId is useful only when sourced from the canonical `error.requestId` envelope and allow-list validated before rendering. A response-header fallback is broader than the stated requirement and should not be retained. ResearchSourceApi currently consumes HTTPException `detail` strings; exposing those in staged UI is avoidable. Save errors should use fixed safe stage messages, while retaining only canonical envelope requestId metadata.

MINIMAL PROVEN DESIGN

1. At GuestWorkspaceSessionRestorer's Author boundary, pass a present persisted document through restoreStudioDocument before AuthorDocumentRuntime.restoreActiveDocument.
2. In restoreStudioDocument, revive only schema-defined Author dates: identity.createdAt, metadata.modifiedAt, REFERENCE.insertedAt, and node.createdAt where that node schema owns it. Reject invalid required/present dates safely. Do not expand AuthorNodeTypes.
3. Keep Inspector as the one authoritative Save Draft owner. Preserve toolbar `.author` download exactly.
4. In Inspector save: prepare command; publish available canonical GRAPH sources first; await the Studio create/version POST; await exact canonical refresh; adopt no fabricated version; preserve runtime document and artifact/projections on every failure. Track a separate local save error with fixed stage-safe copy. Only canonical API-envelope requestId may be rendered after a strict allow-list check.
5. Preserve PDF gates and show that a dirty draft makes an existing saved PDF historical/stale, not deleted.
6. Acquire SQLite BEGIN IMMEDIATE before reading migration history and commit all pending migrations atomically. Retain idempotent reopen, concurrent cold-start, newer-schema, and loud unexpected-failure tests.
